# Локализация

## Текущее состояние

Тексты приложения и Telegram-ботов хранятся в UTF-8 каталоге
[`locale/ru_ru.lang`](locale/ru_ru.lang). Это собственный формат проекта, не
Django gettext: отдельные `.po`/`.mo` файлы и команды `makemessages`/
`compilemessages` не используются.

Сейчас поддержан только русский: `LANGUAGE_CODE` задан как `ru-ru`, в Django
`LANGUAGES` и в настройках пользователя есть только `ru`. Поле языка пользователя
сохраняет выбор, но не переключает перевод: загрузчики приложения и ботов всегда
читают `ru_ru.lang`. Добавления ещё одного файла каталога недостаточно для нового
языка; для этого сначала потребуется реализовать выбор каталога и языка в коде.

## Формат каталога

Каждая запись имеет вид `ключ=значение`:

```text
# Комментарии начинаются с решётки
settings.saved=Изменения сохранены
dashboard.notify_plan=Ближайшее: {description} · {vehicle}
```

Пустые строки и строки-комментарии игнорируются. Разделителем служит первый `=`;
пробелы по краям ключа и значения удаляются. Ключи должны быть уникальными.
Плейсхолдеры записываются в фигурных скобках и передаются в `t()` именованными
аргументами, например `t("settings.saved")` или
`t("dashboard.notify_plan", description=title, vehicle=name)`. Сохраняйте имена
и смысл всех плейсхолдеров при редактировании перевода.

Ключи веб-интерфейса используются в `apps/` и шаблонах через `t()` либо `{% t %}`;
тексты ботов используют тот же файл, обычно с префиксом `bot.`. Если ключа нет,
`t()` возвращает сам ключ. Ошибка форматирования из-за отсутствующего аргумента
также оставляет строку без подстановки; поэтому не переименовывайте и не удаляйте
плейсхолдеры, используемые вызывающим кодом.

## Добавление или изменение перевода

1. Найдите место вызова `t("ключ")` или `{% t "ключ" %}` и используйте тот же
   ключ. Для новой строки добавьте ключ и вызов в соответствующий код одним
   изменением; не встраивайте пользовательский текст прямо во `views.py` или
   `forms.py`.
2. Добавьте или обновите ровно одну запись в `locale/ru_ru.lang`. Для текста бота
   придерживайтесь существующей группы `bot.*`; значения с форматированием должны
   содержать все именованные плейсхолдеры вызова.
3. Проверьте уникальность ключей и покрытие литеральных ключей приложения и
   шаблонов:

   ```sh
   python -m pytest tests/unit/test_localization.py -q
   ```

   `test_localization.py` проверяет дубликаты, известность используемых ключей и
   конвенцию строк во `views.py`/`forms.py`. При изменении текстов ботов также
   запускайте `python -m pytest tests/unit/test_bot_common.py -q`: этот тест
   проверяет поведение переводчика ботов, включая неизвестный ключ и
   форматирование; для него нужны зависимости ботов из `requirements/dev.txt`.
4. Перед отправкой изменений прогоните подходящие проверки из
   [`docs/testing-ci.md`](docs/testing-ci.md). Переводчики загружают файл с
   кэшированием, поэтому после редактирования каталога перезапустите работающий
   процесс приложения или бота, чтобы гарантированно увидеть обновлённый текст.

Для нового языка отдельно понадобятся код поддержки выбора языка и каталога,
настройка списка языков и проверки переключения. До появления этой поддержки не
добавляйте в документацию неподтверждённые коды локалей или заявления о доступных
переводах.
