# Проект диалогов и форматов Telegram-ботов (Этап 4.0)

Аналог «design-first» для ботов: вместо HTML-макетов — карта команд, состояния FSM
пошаговых мастеров, грамматика быстрой записи и форматы ответов. Оба бота работают
клиентами к API-гейтвею `/api/v1/bot/*` (ТЗ 6.2) и авторизуются по `X-Bot-Token`.

Границы ответственности:
- **бот** (aiogram 3.x) — диалог, FSM, парсинг, показ списков, загрузка фото;
- **гейтвей** (Django) — валидация токена, бизнес-правила, запись в БД, справочники.

### 1.1 Бот Бортжурнала (vehicle_bot, ТЗ 7.3)
| Команда | Действие | Источник данных |

| `/purchase` | Мастер покупки | `/bot/ingest create_purchase` |

| `/fine` | Мастер штрафа (+ фото постановления) | `/bot/upload`, `/bot/ingest create_fine` |

## 2. FSM-мастера (пошаговые сценарии)

Общий контракт: мастер собирает поля последовательно; на каждом шаге допускается
`/skip` (для необязательных) и `/cancel` (выход). Перед финальным шагом показывается
карточка-превью, подтверждение `✅ Сохранить` / `✏️ Изменить`.

### 2.1 `/fuel` — заправка (ТЗ 4.2.2)
```
[активное авто?]  ─нет→ /vehicles
1. Пробег (одометр, int)              обяз.
2. Объём, л (dec)                     обяз.
3. Цена за литр (dec)                 обяз.   → сумма = объём×цена (превью)
4. Дата (по умолч. сегодня; «завтра», «Д.М.ГГГГ»)
5. АЗС: InlineKeyboard(недавние+справочник) | «Своя» → текст
6. Полный бак? (да/нет)
7. Примечание (/skip)
→ ingest create_fuel (source=telegram, гео из сообщения, если прислано место)
```

### 2.2 `/purchase` — покупка (ТЗ 4.2.3)
```
1. Название/описание          обяз.
2. Сумма (dec)                обяз.
3. Категория (InlineKeyboard из references/purchase_categories)
4. Дата (по умолч. сегодня)
5. Пробег (/skip)
→ ingest create_purchase
```

### 2.3 `/service` — сервис (ТЗ 4.2.4)
```
1. СТО (название сервиса)     обяз.
2. Описание работ             обяз.
3. Стоимость (dec)            обяз.
4. Дата, пробег (/skip)
5. Фото: 1..N документов → upload (до 10, «готово»/«пропустить»)
→ ingest create_service (photos=[file_id/upload-ключи])
```

### 2.4 `/fine` — штраф (ТЗ 4.2.5)
```
1. Сумма (dec)                обяз.
2. Статья КоАП / описание
3. УИН (decision_number, /skip)
4. Дата (/skip)
5. Статус: не оплачен / оплачен / оспаривается
→ ingest create_fine (link_purchase если оплачен)
```

### 2.5 `/newtask` — задача (ТЗ 4.3.3)
```
scope=work. 1. Заголовок   2. Описание(Markdown)   3. Приоритет
4. Дедлайн (дата/«завтра»)   5. Проект (/skip)   6. Теги   → ingest create_task
```

### 2.6 `/newevent` — событие (ТЗ 4.3.2)
```
scope=personal. 1. Заголовок   2. Начало (дата+время)   3. Окончание/«весь день»
4. Место   5. Проект   6. Приоритет   7. Теги   → ingest create_event
```

## 3. Грамматика быстрой записи `/quick` (ТЗ 7.6, этап 1 — regex + ключевые слова)

Одно свободное сообщение → определение домена и заполнение слотов. Не распознанное →
вопрос-уточнение/переход в мастер.

### 3.1 Общие токены
| Токен | Пример | Регулярка/ключ |
|---|---|---|
| сумма/цена | `2500р`, `2 500 ₽`, `150.5 руб` | `([\d\s.,]+)\s*(р|₽|руб)` |
| объём л | `40л`, `40 л`, `39.5литров` | `([\d.,]+)\s*(л|литр)` |
| пробег | `пробег 125000`, `125 000 км` | `(\d[\d\s]*)\s*(км|пробег)` |
| дата | `сегодня`, `завтра`, `в понедельник`, `15 августа`, `15.08`, `15/08/2026` | словарь + `(\d{1,2})[.\/](\d{1,2})([.\/](\d{2,4}))?` |
| время | `в 15:00`, `15.00` | `(\d{1,2})[:.](\d{2})` |
| тег | `#работа` | `#(\w+)` |
| АЗС | `Лукойл`, `Газпром` | словарь references/fuel_stations |
| категория | `масло`, `фильтр`, `шина` | словарь references/purchase_categories |
| бензин | `95`, `92`, `дизель` | топливные метки |

### 3.2 VehicleBot маршрутизация сообщения
```
содержит «заправ»|«залил»|литры|бензин|92/95/98|дизель  → create_fuel
содержит «купил»|«купили»|«починил»|цена+без_литров     → create_purchase
содержит «сервис»|«сто»|«заказ-наряд»                   → create_service
содержит «штраф»|«гибдд»|«постановлени»|УИН             → create_fine
```
Пример: `Заправил 40л 95го на Лукойле 2500р пробег 125000`
→ `{action:create_fuel, volume:40, fuel_type:95(ai→petrol), station:Лукойл, total:2500, odometer:125000}`.
Сумма/объём/цена: если есть объём и сумма, цена выводится (`сумма/объём`), остальное — как в ТЗ 4.2.2.

### 3.3 PlannerBot маршрутизация
```
содержит время или дату-в-будущем + «встреча/созвон/день рождения» → create_event
иначе (задача/сделать/дедлайн или просто текст с датой)            → create_task
#тег → tags; «завтра в 15:00 … в офисе» → start_at + location
```
Пример: `Завтра в 15:00 встреча в офисе #работа`
→ `{action:create_event, title:'встреча', start_at:'<завтра 15:00>', location:'офис', tags:['работа']}`.

## 4. Форматы ответов и inline (ТЗ 7.5)

- **Списки** (авто/события/задачи/проекты) — пронумерованные карточки `N. <название> — <краткий факт>`
  с InlineKeyboard-навигацией/выбором. Даты — `ДД.ММ`, суммы — с валютой пользователя.
- **Подтверждение записи** — `✅ <что создано>: <ключевые поля> · <id коротко>`.
- **Ошибки 400/401/429** — человекочитаемо: «Неверный токен — проверьте /servers»,
  «Слишком много запросов, подождите».
- **Inline-режим** (ТЗ 7.5):
  - `@vehicle_bot поиск:<запрос>` → `article`-результаты: последние заправки/покупки по АЗС/статье.
  - `@planner_bot задача:<запрос>` → `article`: найденные задачи/события (заголовок, статус, дата).
  - Тап по результату — callback с полным текстом сущности.

## 5. Мульти-серверность (ТЗ 7.1/7.2)

Конфигурация инсталляций хранится на стороне бота (SQLite по `chat_id`), схема:
`{id, name, url, token, is_active}`. Активная инсталляция определяет `base_url`+`token`
для всех обращений к гейтвею. `/addserver` проверяет токен через `POST /bot/ping`.
Токен никогда не логируется. Смена сервера не сбрасывает FSM-состояние мастера.
