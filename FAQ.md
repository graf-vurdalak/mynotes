# Частые вопросы

## Локальная разработка

### На каком адресе открывается приложение в Docker?

Dev Compose публикует Django на `http://localhost:8001/`. Порт `8000` относится к
`runserver` при запуске на хосте через `make run`; это разные сценарии.
Инструкции: [руководство разработки](docs/development.md).

### Где подтверждать регистрацию и смотреть письма?

В dev-конфигурации пустой `EMAIL_HOST` отправляет письма в MailHog. Его веб-интерфейс
доступен на `http://localhost:8025/`, SMTP принимает соединения на порту `1025`.
Регистрация требует подтверждения email. Не настраивайте настоящий SMTP для обычной
локальной разработки.

### Какие способы входа поддерживаются?

Доступны email с паролем и Яндекс OAuth; OAuth требует настроенных учётных данных и
callback URL, приведённого в [INSTALL.md](INSTALL.md). TOTP 2FA можно настроить в
разделе безопасности личного кабинета (`/accounts/settings/security/`).

### Почему загруженные файлы не лежат в папке проекта?

Dev Compose использует SeaweedFS с S3 API и сохраняет данные в Docker volume
`s3_data`; endpoint доступен только внутри Compose-сети. Приложение выдаёт приватные
файлы через авторизованный `/media/<ключ>`, а не прямой публичной ссылкой на бакет.
Настройка production-хранилища и резервного копирования описана в
[документации деплоя](docs/deployment.md).

### Как запустить Telegram-ботов локально?

Боты не нужны для запуска веб-приложения. Для их запуска задайте в локальном `.env`
токены BotFather `TELEGRAM_VEHICLE_BOT_TOKEN` и `TELEGRAM_PLANNER_BOT_TOKEN`, затем
запустите нужный сервис с профилем `bots` (полная команда есть в
[руководстве разработки](docs/development.md)). Для подключения бота к данным нужна
отдельная учётная запись API-токена в личном кабинете `/accounts/tokens/` и адрес
инстанса. API-токен пользователя не является токеном BotFather; созданный токен
показывается только один раз. Не публикуйте ни один из этих токенов.

### Почему бот не проходит авторизацию?

Проверьте, что пользовательский API-токен создан в том же экземпляре приложения,
активен и добавлен в настройки сервера бота через `/addserver`. BotFather-токен
запускает Telegram-клиент, но не заменяет заголовок API `X-Bot-Token`. Отозванный,
просроченный или неверный API-токен приводит к `401`.

### Как безопасно очистить локальную базу и файлы?

`docker compose -f docker-compose.dev.yml down` останавливает сервисы, но сохраняет
именованные volumes. `down -v` удаляет в том числе базу, состояние ботов и файлы
SeaweedFS; используйте его только если намеренно хотите потерять все эти локальные
данные.

## Production и устранение неполадок

### Как развернуть или обновить production?

Используйте [INSTALL.md](INSTALL.md) для установки/обновления и
[docs/deployment.md](docs/deployment.md) для топологии прокси, SeaweedFS/S3,
резервирования и восстановления. Не запускайте production по командам dev Compose.
Продакшен использует опубликованные образы; порядок релизной сборки описан в
[документации CI](docs/testing-ci.md).

### Можно ли использовать локальный `.env.example` в production без изменений?

Нет. Это пример переменных, а не production-конфигурация: задайте реальные домен,
образы и секреты по инструкциям установки. Секреты создавайте/вводите на сервере,
держите `.env` и `s3-prod.json` вне Git и не присылайте их содержимое в логи,
тикеты или чаты.

### Приложение не стартует или отвечает `400 Bad Request`.

В dev проверьте состояние зависимостей командой `docker compose -f
docker-compose.dev.yml ps`, свободен ли порт `8001`, и выполните миграции после
первого запуска. Для production проверяйте `ALLOWED_HOSTS`, домен и прокси по
[INSTALL.md](INSTALL.md). Запрос к production-порту с `Host: 127.0.0.1` может дать
`400`, если этот адрес отсутствует в `ALLOWED_HOSTS`; инструкция установки
показывает проверку с правильным заголовком `Host`.

### Загрузка/просмотр файла завершается ошибкой?

В dev Compose проверьте, что сервис `s3` здоров и что приложение запущено вместе с
ним. В production S3 API не публикуется наружу; проверяйте состояние контейнеров и
логи приложения/S3 по процедурам из [docs/deployment.md](docs/deployment.md).
Не делайте бакет публичным: файлы предназначены для выдачи через приложение.

### Как запустить тесты и почему не собирается E2E-образ?

Точные команды и требования приведены в [docs/testing-ci.md](docs/testing-ci.md).
Первичная сборка E2E-образа требует доступа к сети, чтобы загрузить Chromium
Headless Shell и закреплённую версию axe-core. Проверка мобильных Safari/Chrome
выполняется вручную по [docs/manual-testing.md](docs/manual-testing.md).
